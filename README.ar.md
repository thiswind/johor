# وكيل JOHOR — JOHOR Agent

<div dir="rtl">

وكيل JOHOR هو مساعد ذكي شخصي يعيش على تيليجرام ويخدم مستخدمًا واحدًا محدَّدًا فقط. يجمع بين المحادثة والرؤية وتوليد الصور والبحث المباشر في الويب والصوت بالاتجاهين (استماع وتحدّث) في منظومة واحدة تستضيفها بنفسك وتتحكم بها بالكامل.

![مخطط القدرات](assets/architecture.svg)

- **الدردشة والاستدلال** — يعمل مع أي نقطة نهاية متوافقة مع OpenAI أو Anthropic تُعدّها بنفسك؛ لا ارتباط بأي مورّد
- **الرؤية** — نماذج رؤية GPT تفهم الصور التي يرسلها المستخدم
- **توليد الصور** — `gpt-image-2`
- **البحث المباشر في الويب** — **Perplexity (Sonar) هو محرك البحث الوحيد**، مثبَّت في الإعدادات مع حارس انحراف: إن أصبح غير متاح لأي سبب، يرفع الوكيل خطأً صريحًا بدلًا من التراجع بصمت إلى محرك آخر
- **استخراج الصفحات** — Tavily
- **تحويل الكلام إلى نص** — `gpt-4o-transcribe`
- **تحويل النص إلى كلام** — `gpt-4o-mini-tts`
- **محرك السياق** — ضاغط مدمج يحفظ المحادثات الطويلة بتكلفة معقولة

> لماذا يُثبَّت البحث على Perplexity حصريًا؟ لأن هذا الوكيل يبحث ويقرّر نيابة عن إنسان حقيقي. معدّل هلوسة محركات البحث المجانية أو الرديئة غير مقبول، لذا جودة البحث هنا قيد صارم: الفشل الصريح خير من التدهور الصامت.

## كيف يعمل

```
تيليجرام <-> البوابة <-> نواة الوكيل <-> مزوّدو القدرات
```

تستقبل البوابة تحديثات تيليجرام وتقود حلقة محادثة الوكيل: الأدوات والمهارات والذاكرة ومحرك السياق. يتصل مزوّدو القدرات (الرؤية، توليد الصور، البحث، الاستخراج، الصوت) خلف النواة، لكلٍّ منهم مفتاحه الخاص — أحضر مفاتيحك، احفظها في `config.yaml` ومتغيرات البيئة، ولا ترفعها إلى المستودع أبدًا.

## النشر

![مسار النشر](assets/deployment.svg)

صُمم وكيل JOHOR ليعمل كخدمة systemd مُحصَّنة قليلة الصيانة على خادم لينكس خاص بك:

- **وحدة systemd**، تعمل بمستخدم مخصَّص منخفض الامتياز
- **عزل على مستوى النواة** (مفروض لا استشاري):
  - `ProtectSystem=strict` + `ReadWritePaths=$HOME` — نظام الملفات كله للقراءة فقط عدا مجلد منزل مستخدم الوكيل
  - `ProtectHome=read-only` و`NoNewPrivileges=yes` ومجموعة قدرات فارغة وseccomp `@system-service`
  - فضاء أسماء تحميل خاص
- **لا ترقية ذاتية** — ملف علامة مُدار + متغير بيئة في الوحدة يعطّلان مساري الترقية عبر سطر الأوامر وداخل الدردشة؛ المسار الوحيد هو أن تدفع إلى `main` فيُحدّث الخادم بالدفع السريع
- **مسار الترقية** — آلة التطوير → `git push` → الخادم يسحب بمفتاح نشر للقراءة فقط ويعيد تشغيل الوحدة

## بنية المستودع

```
agent/    حلقة المحادثة الأساسية وعملاء مساعدون
gateway/  بوابة تيليجرام (run.py)
tools/    تطبيقات الأدوات (web_tools.py وغيرها)
plugins/  إضافات مدمجة، منها محرك السياق
skills/   وثائق المهارات
tests/    مجموعة الاختبارات
```

## الفروق عن الأصل

انبثق هذا المشروع كنسخة شجرة عمل من [hermes-agent](https://github.com/NousResearch/hermes-agent) 0.13.0 (أساس بارتكاك واحد، دون تاريخ git مشترك) ويتطور على مساره الخاص. يتضمن الأساس بالفعل هذه التخصيصات:

1. `tools/web_tools.py` — تسجيل احتياطي لمزوّدي الإضافات في `_is_backend_available` (يصلح إسقاط Perplexity بصمت)
2. `tools/web_tools.py` — إنذار انحراف في `_get_capability_backend` (عدم توفر محرك البحث المثبَّت يرفع خطأً صريحًا)
3. `agent/title_generator.py` — `max_tokens` من 500 إلى 1500 (نقاط النهاية بوضع الاستدلال تستهلك الميزانيات الصغيرة)
4. `plugins/context_engine/cursor_style/` — محرك ضغط سياق مخصص
